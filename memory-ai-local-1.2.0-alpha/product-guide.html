01
POSITIONING

它是项目上下文账本，不是另一个聊天机器人。

Git 记录代码发生了什么；Memory AI 记录项目为什么这样做，以及下一位 Agent 需要知道什么。

本地优先

默认留在电脑上

网页服务只监听 127.0.0.1，项目数据保存在本地 SQLite。当前版本不会自动上传到云端。

跨 Agent

上下文不绑定模型

通过 MCP 向支持的 Coding Agent 提供项目摘要、记忆搜索、任务和交接能力。

按需读取

先摘要，再查证据

只在开始项目或遇到具体问题时读取，避免每轮重复发送全部历史。

边界清楚

生活数据不进入开发 Agent

Life Memory 使用独立数据表，现有 MCP 不提供生活照片、人物和故事工具。

Memory AI 不做什么

它不会替代 Git，不会自动读取所有 Agent 私有聊天，也不等于云端向量数据库。当前搜索仍是 SQLite 关键词匹配。

04
QUICK START

第一次使用，按这五步完成。

  1. 01

    启动本地服务

    双击项目文件夹中的 Start Memory AI.cmd。请保持打开的命令窗口运行；关闭窗口就会停止服务。

  2. 02

    打开本地网页

    浏览器通常会自动打开 http://127.0.0.1:3765。本说明书页面可离线直接阅读，但主应用需要本地服务才能读写数据库。

  3. 03

    建立项目空间

    进入“项目记忆”，新建项目并填写目标、工作目录和当前 Agent。目录不会在后台自动监控，只有你点击数据源中的扫描按钮时才会读取。

  4. 04

    添加第一条记忆与任务

    建议先记录一条架构决策、一条失败经验和一个下一步任务。内容应短、具体、可长期复用。

  5. 05

    生成交接包或连接 Agent

    可先在“Agent 交接”中预览和复制交接包；需要自动调用时，再按照“Agent 连接”页面配置本地 MCP。

推荐的第一条记忆

“前端保持原生 HTML/CSS/JS，不引入框架；原因是当前目标是本地可打开的轻量原型。”这比“继续完善前端”更容易被未来的 Agent 正确复用。

05
PROJECT MEMORY

每个项目保存一套独立的开发认知。

DECISION

决策

采用了什么方案，为什么采用，替代方案为什么没有选。

例：SQLite 优先于云数据库，因为首版需要完全本地。
PREFERENCE

偏好

稳定的协作方式、语言、代码风格和产品原则。

例：先给结论，再解释细节。
LESSON

经验

已经验证失败的做法、环境陷阱和避免重复踩坑的结论。

例：关闭命令窗口会使本地页面断开。
CONTEXT

背景

不会频繁变化，但理解项目时必须知道的事实与限制。

例：Developer 与 Life 数据当前只做逻辑分表隔离。

写得好的记忆

  • 一条只表达一个结论
  • 包含原因或适用条件
  • 能在数周后独立读懂
  • 不复制整段原始聊天

应避免的内容

  • 密钥、密码和私人身份信息
  • 没有确认的模型猜测
  • 很快过期的临时进度
  • 与当前项目无关的生活数据

07
MCP CONNECTION

MCP 是本地传输层，不会自动复制全部聊天。

支持 MCP 的 Agent 会在需要时启动 Memory AI 的本地进程，通过标准输入输出调用工具。Codex、Claude Code 和 Antigravity 各有独立的本地凭证，可以在网页立即禁用；断开不会删除数据库中的数据。

list_projects

列出项目与统计

get_project_brief

获取预算内的项目摘要

search_memories

按关键词搜索记忆摘要

get_memory

按 ID 读取一条完整记忆

get_changes

读取指定修订版本后的变化

propose_memory

提交一条待审批的记忆

propose_task_update

提交待审批的任务变更

create_handoff

生成跨 Agent 交接包

连接

  1. 先启动 Memory AI，确认网页可打开。
  2. 在侧栏进入“Agent 连接”。
  3. 选择 Codex、Claude Code 或 Antigravity，获取该客户端独立的本地凭证与配置。
  4. 把配置放入对应客户端，然后重启客户端。
  5. 确认能看到 8 个 memory-ai-local 工具，并在网页运行真实 STDIO 自检。

断开

  1. 在 Memory AI 的 Agent 详情中立即禁用该客户端凭证。
  2. 也可在 Agent 的 MCP 设置中禁用或删除 memory-ai-local。
  3. 重启对应 Agent 客户端，使配置界面同步。
  4. 数据库不会因为断开而删除；其他 Agent 的凭证也不会受到影响。
写保护已启用

网页自检会启动真实 MCP STDIO 子进程，完成初始化、工具发现、读取测试和写保护验证。propose_memory 与 propose_task_update 只创建候选提案，不会绕过网页审批直接修改项目。

省 Token 的调用习惯

  • 01

    项目开始时读一次摘要默认先用约 600 Token 的 brief。

  • 02

    遇到具体问题再搜索不要每轮重复读取全部记忆。

  • 03

    保存长期有效的结论不要把临时闲聊和整段原始对话写入。

  • 04

    切换 Agent 前生成交接先预览，再复制或提供给下一个 Agent。

08
PERMISSIONS & APPROVAL

每个 Agent 独立授权，每次写入先经过人。

本次版本

独立凭证与项目级权限。

Codex、Claude Code 和 Antigravity 使用不同的本地 client ID 与凭证。后端会按项目强制检查读取、搜索、提案、交接和最大上下文预算；网页禁用某一客户端后，该凭证立即失效。

本次版本

敏感过滤与候选写入。

标记为敏感的记忆默认在 SQL 查询层对 Agent 隐藏，只有单独授予敏感读取权限才会返回。Agent 写记忆和改任务只生成 proposal，用户批准后才应用。

安全使用建议

  • 1

    不要保存秘密API Key、密码、身份证件和私人聊天不要写进 Developer Memory。

  • 2

    逐条审查提案确认来源、项目和内容再批准；不确定的提案直接拒绝。

  • 3

    及时禁用不用的连接凭证只保存在本地，但仍应按最小权限原则管理。

  • 4

    只在本机使用不要把 HTTP 地址改成 0.0.0.0，也不要暴露到公网。

09
BACKUP & RECOVERY

完整备份包含索引、关系和 Life 媒体。

本次版本

创建完整备份

在“本地设置”中点击“创建完整备份”，应用会在 data\backups\backup-... 建立新的本地备份目录。

不会上传云端，也不会覆盖旧备份。
本次版本

清单与完整性校验

每份备份包含 developer.json、life.json、media 和带 SHA-256 的 manifest.json。

媒体大小和散列不一致时会拒绝恢复。
本次版本

经过保护的恢复

网页需要在 4.2 秒内再次点击确认；系统先完整校验，再自动创建恢复前安全备份，随后事务恢复数据库并交换媒体目录。

恢复失败时会尽力回滚数据库和媒体目录。
正确操作

创建与恢复

  1. 创建前确认磁盘有足够空间；Life 媒体会被完整复制。
  2. 等待“完整备份已创建”提示，不要在复制过程中关闭命令窗口。
  3. 恢复时先核对备份时间和媒体数量，再连续点击两次“验证并恢复”。
  4. 恢复完成后保留系统自动创建的安全备份，直到你确认项目与媒体都正常。
JSON 导出不是完整备份

单独导出的 Developer 或 Life JSON 只适合查看索引；Life JSON 不包含照片与视频二进制。需要迁移或恢复时，请使用“创建完整备份”。MCP 本地凭证和 token hash 不会进入完整备份。

LIFE MEMORY

生活记忆是独立实验，不向 Coding Agent 开放。

已实现

现在可以做

  • 建立人物空间
  • 导入照片与视频副本
  • 读取 JPEG 的部分 EXIF
  • 保留 HEIC / HEIF 原文件
  • 将同名照片与 MOV 尝试组成 Live Photo
  • 编辑媒体信息与本地故事草稿
限制

需要知道

  • HEIC 在部分 Windows 浏览器不能预览
  • 单个导入文件当前上限为 30 MB
  • Live Photo 目前按文件名配对，可能发生同名误配
  • 故事草稿是本地规则整理，不是云端 AI 生成
  • Life 与 Developer 只是数据库分表，不是物理独立保险库
规划中

尚未提供

  • iPhone 照片库自动监控
  • 完整 HEIC 元数据与缩略图流水线
  • 人脸识别与人物自动归类
  • 声音或形象克隆
  • 生活数据的 MCP 工具
严格边界

现有 MCP 工具完全不提供人物、照片、视频和生活故事。不要把 Life Memory 描述成已经实现的“数字永生”或人物克隆产品。

11
TROUBLESHOOTING

先看现象，再做最小处理。

网页显示“拒绝连接”或 ERR_CONNECTION_REFUSED＋

通常是本地 Node 服务没有运行。重新双击 Start Memory AI.cmd，并保持命令窗口开启，然后刷新网页。

启动窗口出现 EADDRINUSE＋

端口 3765 已被另一个进程占用。先关闭重复启动的 Memory AI 窗口；如果仍存在，请保存错误信息后再排查，不要反复启动多个实例。

Agent 中看不到 MCP 工具＋

确认配置中的本地路径和独立凭证正确，Node.js 版本满足项目要求，并在保存 MCP 配置后重启 Agent。最终应出现 8 个工具。

网页自检通过，但 Agent 仍然无法连接＋

网页自检已经验证 Memory AI 的真实 STDIO 子进程；目标 Agent 仍可能存在配置路径、凭证或客户端重启问题。请检查 Agent 自身的 MCP 日志和配置。

HEIC / HEIF 照片没有预览＋

部分 Windows 浏览器不支持直接显示 HEIC。原文件仍会保留，可从媒体详情中打开；这不代表导入失败。

照片或视频无法导入＋

检查文件是否超过当前 30 MB 单文件限制。大视频和部分 4K Live Photo 可能超出限制，应先保留原文件并等待后续流式导入能力。

换电脑后只有 JSON，没有照片＋

Life JSON 只包含索引，不包含媒体二进制。请改用“创建完整备份”生成同时包含 developer.json、life.json、媒体和校验清单的目录。

备份恢复被拒绝＋

应用会先检查格式、版本、记录关系、文件大小和 SHA-256。任何 JSON 或媒体被修改、缺失或来自不支持的高版本时都会停止恢复，以保护当前数据。

12
FAQ

常见问题。

使用时一定要联网吗？

目前的核心网页、SQLite 和 MCP 都在本机运行，不依赖云端。只有未来主动接入云端模型或同步服务时才需要网络。

为什么还要 MCP？

MCP 让 Agent 按需读写结构化项目数据。手动复制交接包也能工作，但 MCP 能减少重复操作。

它会不会很费 Token？

取决于调用方式。建议每次会话先读一次精简 brief，具体问题再搜索，不要每轮读取完整历史。

现在已经是向量数据库吗？

不是。当前检索使用 SQLite 关键词匹配。语义检索、冲突处理和记忆生命周期属于后续能力。

能直接连接 ChatGPT 和 Claude 所有对话吗？

不能。当前没有实时连接或 ZIP 导入器，也不会自动读取它们的私有会话历史。

可以自动抓取微信聊天吗？

不可以。当前没有微信抓取、联系人选择或数据库解密功能；未来也应只处理用户合法取得并明确选择的数据。

断开 MCP 会删除记忆吗？

不会。禁用某个客户端凭证只会阻止它继续调用 MCP，本地 SQLite 数据和其他 Agent 的凭证仍然保留。

可以把服务开放给局域网吗？

当前不建议。第一版本没有 HTTP 登录系统，请保持只监听 127.0.0.1。

拥有该电脑文件读取权限的人可能直接访问数据库和媒体。请使用 Windows 账户、磁盘加密和可信备份保护整个文件夹。
